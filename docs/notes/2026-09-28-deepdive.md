## Where a cold boot really goes (power button -> chadwm ~6.2 s)
Method: kernel clock zero = rdtsc/2112 MHz (CPUID 15h: 24 MHz x 176/2) minus
CLOCK_MONOTONIC_RAW (not MONOTONIC: ntpd slews it). ~/t480-build/tools/tscmono.c.
| phase | time | notes |
|---|---|---|
| coreboot | 1.29 s | cold (S5). Earlier "0.77 s" figures were warm reboots (0.74-0.86 s) |
|  - dTBT mailbox | 351 ms | scan of 00:1d.0; cold only. Connect_Topology wait (commit 0746511394, added for a TB3 dock hang) is the suspect |
|  - GMA/libgfxinit | 259 ms | ~200 ms is panel_cfg.up_delay_ms (T1+T3) |
|  - FSP-S | 169 ms | |
|  - FSP-M (MRC cached) | 52 ms | |
| GRUB + kernel load + decompress | 1.69 s | 0.75 s menu timeout + ~0.94 s unmeasured (C11 probe splits it) |
| kernel -> /init -> root | 0.47 s | nvme probe 0.32-0.38 s |
| root -> i915 ready | 1.97 s | i915 loads at 2.24 s: udevd starts 0.74 s, modules-load waits for settle |
| startx -> chadwm | 0.60 s | startx 2.65, chadwm 3.25 (kernel-relative) |
- Stock kernel payload: 16.9 MB zstd -> 70.7 MB; userspace zstd -d 108 ms,
  lz4 47 ms. Initramfs 7.8 MB exists only to load nvme (ext4 is =y).
- SPI: IFD fast read 48 MHz, dual output off; measured ~12-14 MB/s, so LZMA
  stays better than LZ4 for the payload (LZ4 would read more bytes).
- CPU runs FIT microcode 0xf5 until FSP-S loads 0xf6 from CBFS; kernel sees
  0xf6, no early update. Harmless.

## Power findings
- AC: package C-states never below PC3 (PC6..PC10 = 0). A/B (RAPL pkg, 20 s):
  current 3.96 W PC3 50% | + PCI runtime PM auto + ASPM powersupersave
  3.53 W, PC8 36% | + powersave gov/EPP0 3.71 W (noise; governor neutral).
- Cause 1: TLP RUNTIME_PM_ON_AC=on (GbE/xHCI/TBT stay D0).
- Cause 2: 00:1d.0 <-> 02:00.0 (TBT upstream) link has ASPM disabled at
  8 GT/s x2: coreboot pciexp_enable_aspm() reads the reserved (0) L1
  acceptable latency of a *switch upstream port* and vetoes L1.
- perf governor pins HWP min=max=42 (4.2 GHz request) on AC; measured no gain
  vs powersave+EPP 0 either way, left as is.
- NVMe KXG6AZNV256G: nvme_core.default_ps_max_latency_us=5500 limits APST to
  PS3 (50 mW). PS4 = 5 mW, 6+14 ms latency, used after 2 s idle at 25000.
- Panel IVO R140NWF5 R6 has no PSR (DPCD 0x070=0, i915 "Sink support: PSR = no")
  -> DC5/DC6 counts 0, PC9/PC10 impossible with screen on. i915.enable_psr=1
  and enable_fbc=1 are defaults/no-ops that only taint the kernel.
- TBT (JHL6240, NVM 23.0) is force-powered forever: gpio.c drives
  TBT_FORCE_PWR, TBT_RTD3_PWR_EN, TBT_FORCE_USB_PWR high; no RTD3 in ACPI.
  Security SL0 + iommu off = no DMA protection on that port.
- Touchscreen excluded from autosuspend (TLP usbhid denylist), rpm active.
- coreboot left PL1 15 W / PL2 18.75 W in MSR 0x610 and MCHBAR until
  thermald-t480 starts; PERF_LIMIT_REASONS logged PL1/PL2 hits.

   linux-t480 boot -> elogind + udevd never started (tty1 login loop, no Wi-Fi, owner had
   to hold the power button); next boot sysctl ran before /proc (swappiness 100).
   Fix: init=/usr/local/sbin/t480-init (execline: mount proc+sys, exec /sbin/init).
   Verified: sysctl applied at boot, cgroup2 mounted, elogind/udevd/X up.
3. C13 dropped ahci/pata/ehci/uhci/ohci/usb preloads (-170 ms of probes) -> NVMe init
   ~56 ms earlier; first NVMe read took 1.59 s on the next boot, and a warm reboot from
